## 2024-05-15 - Making Non-Semantic UI Elements Keyboard Accessible
**Learning:** This application heavily relies on non-semantic HTML elements (`<i>` and `<div>`) for core navigation and primary actions (e.g., `.module-card`, `.action-icon`). Because these elements are not native buttons or links, they completely break keyboard navigation (tabbing) and screen reader support, rendering the application highly inaccessible.
**Action:** Always ensure that non-semantic interactive elements receive `role="button"`, `tabindex="0"`, and proper `aria-label`/`title` attributes. Furthermore, a global JavaScript event listener for the `keydown` event ('Enter' and 'Space') is required to trigger the click action, as the browser only provides this natively for `<button>` and `<a>` tags. Visual focus indicators (`:focus-visible`) must also be explicitly added via CSS.
