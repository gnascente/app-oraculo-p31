## 2026-09-26 - Material Icons and Keyboard Accessibility
**Learning:** The application heavily relies on `<i class="material-icons">` tags as primary action buttons (e.g., `#btnBack`, `#syncIconBtn`, FABs). While adding `role="button"` and `tabindex="0"` improves screen reader visibility and tab order, these generic inline elements do not natively inherit browser-level keyboard event handling (like `<button>` does with Space/Enter). Therefore, developers must ensure a global `keydown` event listener exists to explicitly map 'Enter' and 'Space' keys to `click` events for elements acting as buttons to provide full keyboard accessibility, or explicitly add keyboard handlers when defining new custom icon buttons.
**Action:** When adding new icon-only buttons in the future, if possible, wrap the `<i class="material-icons">` inside a semantic `<button>` tag instead of using the `<i>` tag as the button itself to natively inherit focus and keyboard activation properties. If a `<button>` cannot be used, always verify that `role="button"`, `tabindex="0"`, `aria-label`, and keyboard event handlers are present.
