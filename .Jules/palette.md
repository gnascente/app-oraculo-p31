## 2024-10-27 - Added Focus Indicators and Roles to Interactive Elements
**Learning:** This app frequently relies on non-semantic HTML elements (`<i>` for icons and `<div>` for module cards) acting as primary interactive buttons. This poses a significant accessibility barrier because these elements lack native keyboard focus (`tabindex`) and semantics (`role="button"`), breaking keyboard navigation.
**Action:** Always ensure that when custom DOM elements like `<i>` or `<div>` are used for interactive actions (especially ones with an `onclick` handler), they are explicitly assigned `role="button"`, `tabindex="0"`, a descriptive `aria-label`, and visual `:focus-visible` indicators. A global keydown listener was also implemented to translate 'Enter' and 'Space' keystrokes into click events for these elements.
